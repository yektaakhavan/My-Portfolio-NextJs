نمونه‌کار تنها وب‌سایتی است که نمی‌توانید اجازه دهید کند به نظر برسد. من سایت خودم را گشتم تا ببینم چه چیزهایی واقعاً مهم‌اند، و این پنج تغییر بیشترین اثر را داشتند.

## ۱. به‌جای گرفتن داده در مرورگر، روی سرور رندر کنید

صفحه‌های من اول بارگذاری می‌شدند، بعد JavaScript اجرا می‌شد، بعد محتوا را از یک API می‌گرفت و تازه بعد از آن صفحه پر می‌شد. با منتقل کردن گرفتن داده به server component ها، HTML کامل می‌رسد؛ بدون اسپینر و بدون آبشاری از درخواست‌ها.

## ۲. تصاویر را کوچک کنید

یک اسکرین‌شات مستقیم از گوشی یا ضبط صفحه می‌تواند چند مگابایت باشد. حالا هر آپلود در سایت من به WebP تبدیل و در دو اندازه ذخیره می‌شود. یک تصویر ۲٫۴ مگابایتی به حدود ۱۱۰ کیلوبایت رسید و مرورگر در صفحه‌های کوچک با `srcset` نسخه‌ی کوچک‌تر را برمی‌دارد.

## ۳. چیزهای پایین صفحه را تنبل بارگذاری کنید

تصاویر پایین‌تر صفحه `loading="lazy"` و `decoding="async"` می‌گیرند تا با چیزی که بازدیدکننده اول می‌بیند رقابت نکنند.

## ۴. فونت‌ها را خودتان میزبانی کنید

فونت از یک سرویس شخص ثالث پیش از نمایش متن یک اتصال دیگر اضافه می‌کند و آدرس IP بازدیدکننده‌هایتان را به کس دیگری می‌فرستد. فونت میزبانی‌شده روی خود سایت سریع‌تر شروع می‌شود و توضیح دادنش در سیاست حریم خصوصی ساده‌تر است.

## ۵. فضا را از قبل رزرو کنید تا چیزی نپرد

به تصاویر و کارت‌ها پیش از بارگذاری اندازه‌ی ثابت یا نسبت ابعاد بدهید. بدون آن صفحه هنگام بارگذاری جابه‌جا می‌شود و هم تجربه و هم نمره‌ی Core Web Vitals را خراب می‌کند.

## چیز واقعی را اندازه بگیرید

سرور توسعه خیلی کندتر از نسخه‌ی production است. همیشه با build نهایی اندازه بگیرید، و روی اتصال کند شده‌ای که محدود کرده‌اید، نه فقط روی لپ‌تاپ سریعتان.

```bash
npm run build
npm start
```

بهینه‌سازی بیشتر درباره‌ی برداشتن چیزهاست: درخواست‌های کمتر، بایت‌های کمتر، غافلگیری‌های کمتر.
