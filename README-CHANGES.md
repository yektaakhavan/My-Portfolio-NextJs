# تغییرات سایت — راهنمای اجرا و بررسی

## اجرا (مهم: به ترتیب)

```bash
npm install
cp .env.example .env        # و مقادیر را پر کنید (DATABASE_URL, IP_HASH_SECRET, SITE_URL)
npm run db:push             # جدول‌های جدید/ستون‌های جدید را می‌سازد
npm run build && npm start  # برای سنجش سرعت واقعی از نسخه‌ی production استفاده کنید، نه next dev
```

- `db:push` درباره‌ی **حذف جدول `gallery_items`** سؤال می‌پرسد (چون گالری حذف شد). اگر داده‌ای در آن می‌خواهید، قبلش پشتیبان بگیرید.
- `npm run db:seed` فقط برای دیتابیس **خالی** است و اگر داده وجود داشته باشد از اجرا امتناع می‌کند (قبلاً همه‌چیز را پاک می‌کرد). برای اجبار: `-- --force`.
- بعد از به‌روزرسانی، سشن‌های قدیمی ادمین باطل می‌شوند؛ یک بار دوباره وارد شوید. رمز فعلی شما تغییر نمی‌کند.
- ساخت (`next build`) به دیتابیس نیاز دارد، چون صفحات عمومی از قبل ساخته و کش می‌شوند (ISR، هر ساعت یا فوراً بعد از تغییر در ادمین).

## چه چیزهایی تغییر کرد

| درخواست | وضعیت |
|---|---|
| حذف گالری | صفحه، API، منوی ادمین، آمار و جدول از کد حذف شد |
| دارک/لایت | دکمه‌ی خورشید/ماه در هدر و ادمین؛ پیش‌فرض از تنظیم سیستم؛ بدون پرش رنگ هنگام بارگذاری |
| سرعت | صفحات عمومی سروری و کش‌شده‌اند (قبلاً هر صفحه بعد از لود، دوباره از API داده می‌گرفت)؛ ادمین داده را همراه HTML می‌گیرد؛ فونت‌ها از سرور خودتان؛ عکس‌ها به WebP بهینه می‌شوند |
| drag & drop | در پروژه‌ها و پروفایل؛ با کیبورد هم کار می‌کند؛ برای هر عکس متن alt الزامی-پیشنهادی دارد |
| بک‌اند واقعی | همان Node.js (Next route handlers + PostgreSQL)، با صف تأیید: بخش **Moderation** در ادمین |
| حریم خصوصی/کوکی | صفحات `/privacy`، `/cookies`، `/terms`، `/accessibility` (قبلاً وجود نداشت) |
| دسترس‌پذیری | ادامه‌ی همین فایل |
| رنگ و استایل | بالای `src/app/globals.css` |

## بک‌اند و تأیید پیام‌ها

- فرم **تماس** (`/contact`): خصوصی، به Inbox می‌رود، هرگز منتشر نمی‌شود.
- فرم **پیام عمومی** (`/messages`): با وضعیت `pending` ذخیره می‌شود و تا زمانی که در `/admin/moderation` تأیید نکنید برای هیچ‌کس دیده نمی‌شود. بعد از تأیید، صفحه فوراً به‌روز می‌شود. امکان رد، لغو انتشار و حذف دارد.
- ضد اسپم: فیلد مخفی (honeypot)، حداقل زمان پر کردن، سقف تعداد پیام برای هر IP (۳ در ساعت، ۱۰ در روز؛ IP به‌صورت هش ذخیره می‌شود)، محدودیت لینک، بررسی هم‌مبدأ بودن درخواست.
- لاگین: حداکثر ۶ تلاش ناموفق برای هر ایمیل و ۱۰ برای هر IP در ۱۵ دقیقه. توکن سشن به‌صورت هش در دیتابیس ذخیره می‌شود.
- **اطلاعات ورود نمایشی (`yekta@akhavan.dev / portfolio123`) از صفحه‌ی لاگین حذف شد.** اگر هنوز این رمز را دارید، همین حالا عوضش کنید.

## رنگ و استایل (نقد صادقانه)

پالت فعلی (بنفش تیره + طلایی + پس‌زمینه‌ی ستاره‌ای + فونت سریف) **تکراری و شبیه قالب‌های آماده** است و حس «برند لوکس/نویسنده» می‌دهد، نه «فرانت‌اند دولوپر». به‌صورت پیش‌فرض همان را نگه داشتم (با نسخه‌ی لایت هماهنگ) و سه جایگزین آماده را **کامنت‌شده** در `globals.css` گذاشتم:

- **B — Ink & Teal:** فنی و تمیز  
- **C — Paper & Vermilion (پیشنهاد من):** کاغذ گرم + نارنجی-قرمز؛ با فونت سریف فعلی هماهنگ و متمایز  
- **D — Slate & Electric Blue:** حرفه‌ای و کم‌ریسک

برای تعویض: بلوک «ACTIVE PALETTE» را پاک کنید و یکی از بلوک‌های کامنت‌شده را از حالت کامنت دربیاورید. کنتراست همه‌ی گزینه‌ها در دارک و لایت با محاسبه‌ی WCAG بررسی شده است.

## دسترس‌پذیری — چه بررسی شد و چه نشد

انجام شد: لینک پرش به محتوا، landmark ها، یک `h1` در هر صفحه، alt برای عکس‌ها (و فیلد alt در ادمین)، برچسب و پیام خطای وصل‌شده به هر فیلد، فوکوس قابل‌دیدن، دیالوگ‌ها با trap فوکوس و Escape، دکمه‌ها با نام واضح (مثلاً «Delete project X»)، حذف ساختار نامعتبر `<a><button>` که هر کنترل را دو بار در Tab می‌آورد، احترام به `prefers-reduced-motion`، `aria-current`/`aria-pressed`/`aria-expanded` در منوها و فیلترها. ابزار axe-core روی ۲۰ صفحه (عمومی و ادمین) اجرا شد: **۰ مورد**. کنتراست رنگ‌ها عددی محاسبه شد.

**انجام نشد و باید خودتان ببینید:** تست با screen reader واقعی (NVDA/VoiceOver) و تست دستی در مرورگر؛ axe در jsdom کنتراست را نمی‌سنجد. متن alt برای عکس‌های واقعی پروژه‌ها را باید خودتان بنویسید.

## قبل از انتشار

1. متن صفحات حقوقی را بخوانید و با وضعیت واقعی خودتان (کشور، مدت نگهداری ایمیل‌ها، میزبان) تطبیق دهید؛ من وکیل نیستم.  
2. `IP_HASH_SECRET` را یک رشته‌ی تصادفی بلند بگذارید و سایت را روی HTTPS اجرا کنید.  
3. پوشه‌ی `uploads/` (یا `UPLOAD_DIR`) را پشتیبان‌گیری کنید؛ عکس‌های آپلودشده آنجا هستند.  
4. عکس‌های اصلی در `src/assets` توسط سایت استفاده **نمی‌شوند**؛ از پنل ادمین آپلودشان کنید.  
5. اگر آنالیتیکس اضافه کردید، سیاست کوکی و حریم خصوصی را به‌روز کنید و رضایت بگیرید.

# به‌روزرسانی دوم — شش تغییر درخواستی

## اجرا بعد از به‌روزرسانی

```bash
npm install            # بسته‌های جدید: dnd-kit (جابه‌جایی) و react-markdown (توضیحات پروژه)
npm run db:push        # ستون جدید `details` را به جدول projects اضافه می‌کند (داده‌ها دست نمی‌خورند)
npm run build && npm start
```

اگر از مایگریشن‌های پوشه‌ی `drizzle/` استفاده می‌کنی به‌جای `db:push`: `npx drizzle-kit generate` و بعد `npx drizzle-kit migrate`.

## چه چیزی تغییر کرد

1. **عکس بلندتر، کپشن کوچک‌تر:** عکس کارت از ۱۷۶ به ۲۲۴ پیکسل (در دسکتاپ ۲۴۰) رفت و از **بالای** عکس برش می‌خورد (برای اسکرین‌شات سایت‌ها، هدر مهم‌تر از وسط صفحه است). عنوان و توضیح کوچک‌تر شد.
2. **حداکثر ۳ بج روی عکس** (در کارت‌ها و هدر صفحه‌ی پروژه).
3. **صفحه‌ی اصلی حداکثر ۴ بج تکنولوژی** نشان می‌دهد. در `/projects` و در صفحه‌ی خود پروژه همه نمایش داده می‌شوند (صفحه‌ی پروژه همه‌ی تگ‌ها را هم در یک بخش جدا دارد).
4. **ارتفاع ثابت کارت:** هر بخش (عکس، عنوان، توضیح، بج‌ها، دکمه‌ها) اندازه‌ی ثابت دارد، پس همه‌ی کارت‌ها هم‌قد می‌مانند.
5. **جابه‌جایی با drag & drop** در ادمین → Projects و Skills: دستگیره‌ی ⋮⋮ را بکش. با کیبورد هم کار می‌کند: روی دستگیره Tab بزن، Space = برداشتن، فلش‌ها = جابه‌جایی، Space = گذاشتن، Esc = لغو. ترتیب خودکار ذخیره می‌شود و روی سایت عمومی (از جمله پروژه‌های صفحه‌ی اصلی) اعمال می‌شود.
6. **صفحه‌ی اختصاصی + ادیتور:** کل کارت قابل کلیک است و به `/projects/<slug>` می‌رود. در ادمین → Projects دکمه‌ی **Write-up** هر پروژه، ادیتور Markdown با نوار ابزار، پیش‌نمایش زنده، دکمه‌ی «Insert template» (چالش‌ها / چیزی که یاد گرفتم / نتیجه) و Ctrl+S دارد. متن در بخش «Behind the project» نمایش داده می‌شود و اگر خالی باشد آن بخش نیست. متن فارسی خودکار راست‌به‌چپ می‌شود. HTML خام، اسکریپت، لینک `javascript:` و عکس بیرونی در متن اجازه ندارند.

## چیزهایی که در پروژه‌ی خودت دیدم (تغییر ندادم)

- در `globals.css` هم پالت **C** و هم **D** از حالت کامنت درآمده‌اند. چون D پایین‌تر است، **D (آبی) برنده است**، نه C. اگر C را می‌خواهی، بلوک D را دوباره کامنت کن.
- `layout.tsx` الان **هم** فونت‌های محلی (fontsource) را import می‌کند **و هم** از Google Fonts لینک می‌گیرد (و نام فونت‌ها در CSS تغییر کرده). صفحه‌ی Privacy و Cookie می‌گویند فونت‌ها روی همین سایت هستند و با Google ارتباط نیست؛ با لینک Google این جمله درست نیست. یا لینک‌ها را بردار و نام فونت‌ها را به `"Manrope Variable"` و `"Fraunces Variable"` برگردان، یا متن آن دو صفحه را اصلاح کن.

# به‌روزرسانی سوم — سایت دوزبانه (انگلیسی + فارسی)

## اجرا بعد از به‌روزرسانی

```bash
npm install            # بسته‌ی جدید: فونت وزیرمتن (@fontsource-variable/vazirmatn)
npm run db:push        # ستون‌های جدید `translations` را اضافه می‌کند (داده‌های فعلی دست نمی‌خورند)
npm run build && npm start
```

## ⭐ چطور زبان پیش‌فرض را عوض کنم؟

فایل **`src/i18n/config.ts`** را باز کن و این خط را پیدا کن:

```ts
export const DEFAULT_LOCALE: Locale = "en"; // ⭐ <— change to "fa" to make Persian the default
```

`"en"` را به `"fa"` تغییر بده، ذخیره کن و دوباره `npm run build` (یا در حالت توسعه، `npm run dev` را از نو) اجرا کن. همین! هیچ جای دیگری لازم نیست دست بزنی. من هر دو حالت را امتحان کرده‌ام. نتیجه:

| آدرس | پیش‌فرض `en` | پیش‌فرض `fa` |
|---|---|---|
| `/` و `/about` | انگلیسی | **فارسی** |
| `/fa` و `/fa/about` | فارسی | به `/` و `/about` ریدایرکت می‌شود |
| `/en` و `/en/about` | به `/` و `/about` ریدایرکت می‌شود | انگلیسی |

نکته‌ها:
- زبان پیش‌فرض **بدون پیشوند** است و زبان دیگر با پیشوند (`/fa/...` یا `/en/...`).
- اگر جایی لینک انگلیسی (مثلاً `/projects/my-app`) منتشر کرده‌ای و پیش‌فرض را به `fa` ببری، آن لینک‌ها از آن به بعد **صفحه‌ی فارسی** را نشان می‌دهند. برای انگلیسی باید `/en/projects/my-app` باشد.
- `lang` و `dir` (چپ‌به‌راست / راست‌به‌چپ)، فونت، لینک‌های داخلی، sitemap و تگ‌های hreflang خودکار تغییر می‌کنند.
- سایت **زبان مرورگر بازدیدکننده را تشخیص نمی‌دهد**؛ عمداً: همیشه زبان پیش‌فرض نمایش داده می‌شود و بازدیدکننده با دکمه‌ی «فارسی / English» در هدر عوض می‌کند.
- پنل ادمین و صفحه‌ی ورود همیشه انگلیسی هستند.

## متن‌های سایت (دکمه‌ها، عنوان‌ها، پیام‌ها)

- انگلیسی: `src/i18n/messages/en.ts` — فارسی: `src/i18n/messages/fa.ts`. هر دو فایل باید کلیدهای یکسان داشته باشند و TypeScript اگر کلیدی جا افتاده باشد خطا می‌دهد.
- جاهایی مثل `{name}` یا `{n}` را دست نزن؛ کد آن‌ها را پر می‌کند.
- صفحات حقوقی (حریم خصوصی، کوکی، شرایط، دسترس‌پذیری): `src/content/legal/*.en.tsx` و `*.fa.tsx`. **ترجمه‌ی فارسی را یک نفر که حقوقی/نگارشی بلد است بخواند**؛ من وکیل نیستم.

## محتوای خودت (بیو، پروژه‌ها، مهارت‌ها)

در ادمین، هر جا «Persian version (فارسی)» می‌بینی همان است:

- **Profile:** بخش «Persian version» (نام، عنوان، بیو، ویژگی‌ها، سابقه کاری و تحصیلات). دکمه‌ی «Copy the English entries here to translate» ساختار انگلیسی را برایت کپی می‌کند تا فقط ترجمه کنی.
- **Projects → Edit:** عنوان، توضیح و تگ‌های فارسی. **Projects → Write-up:** دو تب «English» و «فارسی» برای توضیحات اضافه.
- **Skills → Edit:** «Name in Persian» (برای مهارت‌های نرم مثل Teamwork؛ نام ابزارها مثل Git را خالی بگذار).

قانون مهم: **هر فیلد فارسی که خالی بماند، در صفحات فارسی متن انگلیسی نمایش داده می‌شود.** پس می‌توانی کم‌کم ترجمه کنی و هیچ جای خالی‌ای دیده نمی‌شود. عکس، ایمیل، تلفن و لینک‌ها بین دو زبان مشترک‌اند.

## اضافه کردن زبان سوم (اختیاری)

۱) کد زبان را به `LOCALES` و `LOCALE_META` در `src/i18n/config.ts` اضافه کن. ۲) `src/i18n/messages/en.ts` را کپی و ترجمه کن و در `src/i18n/index.ts` ثبتش کن. ۳) متن‌های حقوقی را بنویس. توجه: ترجمه‌ی محتوای دیتابیس فعلاً فقط برای فارسی (`translations.fa`) آماده است.

## چیزهایی که باید بدانی

- **چیدمان راست‌به‌چپ را در مرورگر واقعی ندیدم** (مرورگری در دسترس نبود). ساختار، جهت‌ها (ویژگی‌های منطقی مثل `ms-`/`start-`، آیکون فلش آینه‌شده) و همه‌ی صفحات فارسی و انگلیسی با axe بررسی شدند، ولی ظاهر بصری را حتماً خودت یک بار نگاه کن (مخصوصاً کارت پروژه‌ها و هدر).
- فونت فارسی **وزیرمتن** است و از خود سایت سرو می‌شود (به Google وصل نیست). فاصله‌ی حروف (`tracking`) در فارسی خاموش شده، چون حروف فارسی را از هم جدا می‌کند.
- تاریخ‌ها و عددها در صفحه‌ی فارسی به قالب فارسی (ارقام فارسی و تقویم شمسی برای تاریخ پیام‌ها) نمایش داده می‌شوند.
- صفحه‌ی ۴۰۴ در HTML اولیه `lang` ندارد (تا اجرای جاوااسکریپت)؛ به‌خاطر داشتن دو layout ریشه‌ای (سایت و ادمین). پس از اجرای JS درست می‌شود.
- برای توسعه‌دهنده: بعد از تغییر محتوا در ادمین، صفحات با `revalidatePath("/(site)/[locale]", "layout")` تازه می‌شوند. **نام گروه `(site)` باید در مسیر باشد**؛ بدون آن بی‌صدا هیچ کاری نمی‌کند. همچنین `dynamicParams = false` را روی `[locale]` نگذار: صفحه‌های تازه‌شده ۴۰۴ می‌دهند.
- اگر فونت Google در `root-document.tsx` را نگه می‌داری، جمله‌ی «فونت‌ها روی همین سایت هستند» در صفحات حریم خصوصی و کوکی (هر دو زبان) درست نیست.

# به‌روزرسانی چهارم — بلاگ، رفع عکس‌ها، فونت و ادیتور

## اجرا بعد از به‌روزرسانی

```bash
npm install
npm run db:push            # جدول جدید articles را می‌سازد (داده‌های فعلی دست نمی‌خورند)
npm run db:seed:articles   # ۶ مقاله‌ی نمونه را اضافه می‌کند (فقط یک بار؛ اگر دوباره بزنی چیزی را بازنویسی نمی‌کند)
npm run build && npm start
```

## ۱) باز شدن عکس پروژه‌ها

**علت:** انیمیشن ورود صفحه (`fade-up`) روی `<main>` بعد از پایان یک `transform` روی آن باقی می‌گذاشت. برای هر عنصر `position: fixed` داخل `main` این یعنی «نسبت به همان main ثابت باش، نه نسبت به صفحه‌ی نمایش»؛ پس نمایشگر عکس جایی در پایین صفحه‌ی بلند باز می‌شد و زیر هدر می‌رفت.
**رفع:** نمایشگر عکس و همه‌ی پنجره‌ها (Modal) حالا با portal مستقیم زیر `<body>` رندر می‌شوند و انیمیشن طوری عوض شد که transform باقی نگذارد. در یک DOM آزمایشی (jsdom) تأیید شد که پنجره حتی داخل یک `main` با transform هم فرزند مستقیم `body` است و فوکوس داخلش می‌رود.

## ۲) بلاگ

- **`/blog`** (و `/fa/blog`): فهرست مقاله‌ها با تاریخ نگارش، زمان مطالعه، حداکثر ۳ برچسب روی عکس، فیلتر با برچسب و جستجو. لینک `/blog?tag=CSS` مستقیم فیلتر می‌کند.
- **صفحه‌ی مقاله:** عنوان، تاریخ، زمان مطالعه، برچسب‌ها (کلیک‌پذیر و فیلتر می‌کنند)، عکس کاور با alt، متن، دکمه‌های «مقاله‌ی جدیدتر / قدیمی‌تر» و بخش «ادامه‌ی مطالعه» با ۳ مقاله‌ی مرتبط (اول آن‌هایی که برچسب مشترک دارند).
- **صفحه‌ی اصلی:** اسلایدر کوچک ۴ تازه‌ترین مقاله، نزدیک انتهای صفحه (قبل از بخش تماس). بدون پخش خودکار (برای دسترس‌پذیری)؛ با لمس، چرخ ماوس، دکمه‌های قبلی/بعدی و Tab کار می‌کند و در حالت راست‌به‌چپ هم درست است.
- **ادمین → Articles:** ساخت، ویرایش و حذف. هر مقاله **پیش‌نویس (Draft)** هم می‌تواند باشد که فقط خودت می‌بینی. تاریخ نگارش را خودت تعیین می‌کنی. نسخه‌ی فارسی عنوان، خلاصه، برچسب‌ها، alt کاور و متن مقاله جداست و اگر خالی بماند انگلیسی نشان داده می‌شود.
- **مقاله‌های نمونه:** ۶ مقاله (انگلیسی + فارسی) درباره‌ی چیزهایی که در همین پروژه انجام شد. من نوشتمشان؛ **حتماً بخوان، ویرایش کن یا پاک کن** تا با صدای خودت باشند. فایل‌های اصلی در `src/content/blog/` هستند.
- **عکس مقاله‌ها** را خودم با کد ساختم (`node scripts/make-covers.mjs`) و در `public/images/blog/` هستند. هر زمان بخواهی از ادمین عکس خودت را جایگزین کن (drag & drop).

## ۳) فونت

لینک Google Fonts برداشته شد؛ فقط فونت‌های میزبانی‌شده روی خود سایت (Manrope، Fraunces، وزیرمتن) استفاده می‌شوند. بررسی شد که در HTML و CSS هیچ اشاره‌ای به googleapis/gstatic و هیچ `url(http…)` نیست و فایل‌های `woff2` از خود سایت سرو می‌شوند. پس جمله‌ی «فونت‌ها روی همین سایت هستند» در صفحات حریم خصوصی و کوکی دوباره درست است.

## ۴) ادیتور توضیحات پروژه

دکمه‌ی جدای «Write-up» و صفحه‌ی `/admin/projects/<id>/details` حذف شدند. ادیتور (نوار ابزار، دکمه‌ی «Insert template»، تب Write / Preview و انتخاب زبان English / فارسی) حالا **داخل پنجره‌ی Edit همان پروژه** است. همین ادیتور برای متن مقاله‌ها هم استفاده می‌شود.
